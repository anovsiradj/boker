## 0. Ringkasan Masalah

Setelah URL didaftarkan, halaman masih bisa diakses karena dynamic rule `declarativeNetRequest` (DNR) tidak pernah dibuat.

**Akar masalah (F1):** `src/popup/index.ts:93-97` hanya mengirim `UPDATE_RULES` di dalam guard `if (!domains.includes(parsed.hostname))`. Karena `INSERT_HOST` sudah menulis host ke DB sebelum baris itu, guard selalu `false`, sehingga `saveBlockedDomains()` tak pernah dipanggil dan `updateRules()` di background tak pernah jalan.

Bukti runtime: setelah 3 add via UI, `chrome.declarativeNetRequest.getDynamicRules()` = `[]`.

---

## 1. Tujuan

1. Membuat penambahan URL via UI **selalu** menghasilkan dynamic DNR rule.
2. Memperbaiki pola matching DNR agar tidak salah blokir domain lain (F3).
3. Memperbaiki E2E test agar valid dan mendeteksi regresi (F4).
4. Merapikan hardening minor (F5).

## 2. Non-Tujuan

- Tidak mengubah arsitektur (popup -> background -> offscreen -> worker -> SQLite/OPFS).
- Tidak menambah fitur baru (mis. wildcard/path blocking) pada iterasi ini.
- Tidak menyentuh Firefox/Safari.

### Fase 1 — CRITICAL: Sinkronisasi rule saat add (F1)

**Masalah:** `UPDATE_RULES` tak terkirim saat add.

**Perubahan** — `src/popup/index.ts` (blok setelah `INSERT_LINK`):

```ts
// SEBELUM
const domains = await loadBlockedDomains();
if (!domains.includes(parsed.hostname)) {
  domains.push(parsed.hostname);
  await saveBlockedDomains(domains);
}

// SESUDAH
const domains = await loadBlockedDomains();
// Jaga-jaga terhadap race cold-start: pastikan host ada, lalu SELALU sinkronkan rule.
if (!domains.includes(parsed.hostname)) domains.push(parsed.hostname);
await saveBlockedDomains(domains);
```

**Verifikasi:**
- [x] Build, load extension, add 1 domain -> `getDynamicRules()` berisi rule `block` untuk domain itu (E2E).
- [x] Add domain ke-2 dan ke-3 -> rule bertambah (idempoten: replace dari DB).
- [x] Navigasi ke domain terdaftar -> `net::ERR_BLOCKED_BY_CLIENT` (E2E).
- [x] Remove domain -> rule ikut terhapus (handler remove sudah memanggil `saveBlockedDomains`).

**Catatan:** karena DB adalah source of truth, `updateRules()` idempoten (hapus semua rule lama, tulis ulang dari daftar DB).

## 8. Risiko & Mitigasi

| Risiko | Mitigasi |
|--------|----------|
| `requestDomains` tidak didukung Chrome lama | Set `minimum_chrome_version` atau fallback `||domain/` |
| Race cold-start offscreen masih ada | Fase 1 sudah defensif (`if (!includes) push` + selalu sync) |
| Test false-positive karena DNS | Assert pada `getDynamicRules()` + cek `ERR_BLOCKED_BY_CLIENT` |
| Dynamic rule menumpuk / limit 5000-30000 | `updateRules` selalu replace dari DB, aman |

## Lampiran A — Hasil Audit & Bukti Runtime

### A.1 Alur blocking sesuai desain

```
Popup (add URL)
  -> INSERT_HOST / INSERT_LINK   (background -> offscreen -> worker -> SQLite)
  -> GET_BLOCKED_DOMAINS
  -> UPDATE_RULES { domains }
       -> chrome.declarativeNetRequest.updateDynamicRules({ removeRuleIds, addRules })
```

`updateRules()` hanya dipanggil dari:
| Lokasi | Kapan | Berfungsi? |
|--------|-------|-----------|
| `src/background/index.ts` (`UPDATE_RULES`) | add/remove via popup | Dulu tidak pernah saat add (F1); kini selalu |
| `src/background/index.ts` (`IMPORT_DB`) | import DB | Ya |
| `src/background/index.ts` (`onInstalled`) | install/update | Ya (hanya saat itu) |

### A.2 Bukti runtime (warm state, sebelum perbaikan)

```
TRACE: [
  ["GET before",       { "domains": [] }],
  ["INSERT_HOST",      { "hostId": 1 }],
  ["GET after insert", { "domains": ["trace-domain.com"] }]   <-- host langsung terlihat
]
After UI add https://first.example.com  -> rules: []
After UI add https://second.example.com -> rules: []
After UI add https://third.example.com  -> rules: []
FINAL rules: []
```

`GET after insert` membuktikan host sudah ada di DB tepat setelah insert -> guard `!domains.includes(...)` pasti `false`.

### A.3 Bukti F2 (race cold-start)

| Percobaan | Kondisi | Hasil rule |
|-----------|---------|-----------|
| Run #1 (cold) | add langsung setelah load | `[{"id":1000,"filter":"||example.com"}]` (kebetulan berhasil) |
| Run #2 (warm) | offscreen/worker siap | `[]` (gagal) |

Menjelaskan mengapa perilaku tampak tidak konsisten.

### A.4 Bukti F4 (test timeout)

```
test-results/tests-blocking-.../error-context.md:
Test timeout of 30000ms exceeded.
```

Penyebab: `browserContext.backgroundPages()` selalu kosong di MV3 (memakai service worker).

## Lampiran B — Kutipan Docs Resmi (DNR)

`declarativeNetRequest` -> "Write good URL conditions":

> `||google.com` incorrectly matches `https://google.company`
> Consider using: `||google.com/`, which matches all paths and all subdomains.

Catatan permission: `declarativeNetRequest` memberi akses implisit untuk rule `block` (sudah dipakai). Dynamic rule **persisten** lintas sesi & upgrade, jadi tidak perlu re-add saat startup.
